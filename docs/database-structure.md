# Database Structure

TaskMetrics uses **Firebase Firestore** as its primary database with an in-memory fallback when Firebase is unavailable. This document describes both the Firestore collection structure and the in-memory data model.

---

## Firebase Firestore Collections

### `tasks` Collection

**Purpose:** Stores all task documents. Each document represents a single task owned by a user.

| Field | Type | Description |
|-------|------|-------------|
| `userId` | `string` | Firebase UID or demo user ID. Used to query tasks for the authenticated user. |
| `title` | `string` | Task title. Trimmed on save. |
| `description` | `string` | Optional task description. Trimmed on save. |
| `category` | `string` | One of: `"Work"`, `"Personal"`, `"Study"`, `"Health"`, `"Other"` |
| `status` | `string` | One of: `"pending"`, `"in_progress"`, `"completed"` |
| `deadline` | `Timestamp` | Optional due date. Stored as Firebase Timestamp, serialized to ISO string in the app. Null if not set. |
| `reminderAt` | `Timestamp` | Optional reminder datetime. Stored as Firebase Timestamp, serialized to ISO string in the app. Null if not set. |
| `notificationId` | `string` | Expo notification ID for the scheduled reminder. Used to cancel/reschedule notifications. Null if no reminder is scheduled. |
| `soundName` | `string` | Selected alarm sound: `"default"` or `"alarm"`. Defaults to `"default"`. |
| `createdAt` | `Timestamp` | Server timestamp when the task was created. |
| `updatedAt` | `Timestamp` | Server timestamp when the task was last updated. |

**Document ID:** Auto-generated by Firestore (`addDoc` generates a unique ID).

**Indexes:**
- A composite index on `userId` + `createdAt` is implicitly created for the query `where("userId", "==", user.uid)` ordered by default.

---

### `users` Collection

**Purpose:** Stores user profile documents. Created during registration.

| Field | Type | Description |
|-------|------|-------------|
| `displayName` | `string` | User's full name from registration |
| `email` | `string` | User's email address |
| `createdAt` | `Timestamp` | Server timestamp when the account was created |

**Document ID:** Matches the Firebase Authentication UID.

## In-Memory Data Model (Demo / Fallback Mode)

When Firebase is unavailable (configuration missing or initialization fails), the app operates entirely in memory.

### Task Object Shape

```javascript
{
  id: "1234567890_abcde",          // Generated: Date.now() + random string
  userId: "demo_1234567890",       // Generated: "demo_" + Date.now()
  title: "Buy groceries",           // User input, trimmed
  description: "Milk, eggs, bread", // User input, trimmed, or ""
  category: "Personal",             // From CATEGORIES constant
  status: "pending",                // "pending" | "in_progress" | "completed"
  deadline: "2026-06-15T00:00:00.000Z", // ISO string or null
  reminderAt: "2026-06-14T09:00:00.000Z", // ISO string or null
  notificationId: "abc-def-123",   // Expo notification ID or null
  soundName: "default",             // "default" | "alarm"
  createdAt: "2026-06-10T12:00:00.000Z", // ISO string
  updatedAt: "2026-06-10T12:30:00.000Z", // ISO string
}
```

### In-App Notification Object Shape

```javascript
{
  id: "1234567890_fghij",          // Generated: Date.now() + random string
  type: "completed"                 // "completed" | "deleted"
  taskTitle: "Buy groceries",       // Title of the affected task
  timestamp: "2026-06-10T12:30:00.000Z", // ISO string
}
```

The in-app notification list is capped at 20 entries.

## Relationships

```
User (Auth)
  │
  │  owns / creates
  │
  ▼
Tasks ──────► Notification (local)
  │                │
  │                └── Scheduled via expo-notifications
  │                    Uses taskId for tap navigation
  │
  └──► In-App Notifications (in-memory)
       Linked to task title for display only
       Not stored in Firestore
```

### Key Relationships:

| Relationship | Type | Description |
|-------------|------|-------------|
| User → Tasks | One-to-Many | A user can have many tasks. Each task belongs to one user. |
| Task → Notification | One-to-One (optional) | A task can have at most one scheduled notification. The `notificationId` field links them. |
| Task → In-App Notification | One-to-Many (in-memory) | Task completions and deletions generate in-app notifications. Not persisted. |

### Query Pattern:

When a user logs in, the app establishes a Firestore listener:

```javascript
query(collection(db, "tasks"), where("userId", "==", user.uid))
```

This returns all tasks belonging to the authenticated user in real time. The listener updates the local state whenever data changes in Firestore.

## Firebase Security Rules (Suggested)

> **TODO:** The current project does not include Firebase Security Rules. Below are suggested rules for production deployment.

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Tasks: users can only read/write their own tasks
    match /tasks/{taskId} {
      allow read, update, delete: if request.auth != null 
        && request.auth.uid == resource.data.userId;
      allow create: if request.auth != null 
        && request.auth.uid == request.resource.data.userId;
    }
    
    // Users: users can read/write their own profile
    match /users/{userId} {
      allow read, update: if request.auth != null 
        && request.auth.uid == userId;
      allow create: if request.auth != null 
        && request.auth.uid == request.resource.data.uid;
    }
  }
}
```
